# Confd Dynamic Plugin Architecture Demo

This guide will walk you through testing the entirely new **HashiCorp `go-plugin`** architecture of `confd`. 
Instead of using a statically compiled backend, we will use a standalone compiled binary (`confd-plugin-postgres`) that `confd` will communicate with dynamically over RPC!

---

## 1. Preparation & Compilation

First, make sure both the main `confd` binary and our external Postgres plugin are compiled up to date.

```bash
# 1. Vendor dependencies
go mod vendor

# 2. Compile the core confd binary
make build

# 3. Compile the standalone Postgres Plugin
go build -o bin/confd-plugin-postgres ./cmd/confd-plugin-postgres
```

---

## 2. Start PostgreSQL

We will use the same Docker environment as before. Start it up:

```bash
docker compose -f test/docker-compose.yml up -d postgres
```

Wait a few seconds for the database to boot, then create the table and the triggers (which act as our configuration safety net):

```bash
docker compose -f test/docker-compose.yml exec -T postgres psql -U admin -d confd -c "
DROP TABLE IF EXISTS confd_config CASCADE;
DROP TABLE IF EXISTS config_audit CASCADE;

-- Create core table and audit table
CREATE TABLE confd_config (key VARCHAR(255) PRIMARY KEY, value TEXT);
CREATE TABLE config_audit (id SERIAL, action VARCHAR(10), key VARCHAR(255), old_value TEXT, new_value TEXT, changed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, changed_by VARCHAR(50));

-- Trigger 1: Validation (Prevent bad ports)
CREATE OR REPLACE FUNCTION validate_config() RETURNS TRIGGER AS \$\$
BEGIN
    IF NEW.key = '/app/database/port' AND (NEW.value::int < 1 OR NEW.value::int > 65535) THEN
        RAISE EXCEPTION 'Invalid port number: %', NEW.value;
    END IF;
    RETURN NEW;
END; \$\$ LANGUAGE plpgsql;
CREATE TRIGGER trigger_validation BEFORE INSERT OR UPDATE ON confd_config FOR EACH ROW EXECUTE FUNCTION validate_config();

-- Trigger 2: Audit Trail
CREATE OR REPLACE FUNCTION log_audit() RETURNS TRIGGER AS \$\$
BEGIN
    IF (TG_OP = 'UPDATE') THEN INSERT INTO config_audit (key, old_value, new_value, action) VALUES (OLD.key, OLD.value, NEW.value, 'UPDATE');
    ELSIF (TG_OP = 'INSERT') THEN INSERT INTO config_audit (key, old_value, new_value, action) VALUES (NEW.key, NULL, NEW.value, 'INSERT');
    END IF; RETURN NULL;
END; \$\$ LANGUAGE plpgsql;
CREATE TRIGGER trigger_audit AFTER INSERT OR UPDATE ON confd_config FOR EACH ROW EXECUTE FUNCTION log_audit();

-- Insert initial values
INSERT INTO confd_config (key, value) VALUES ('/app/database/host', 'db-master.internal'), ('/app/database/port', '5432'), ('/app/feature_flags/maintenance', 'false');
"
```

## 3. Create the Confd Workspace

We will create a fresh workspace in `/tmp/confd-plugin-demo`.

```bash
mkdir -p /tmp/confd-plugin-demo/conf.d
mkdir -p /tmp/confd-plugin-demo/templates
mkdir -p /tmp/confd-plugin-demo/output

# Create the resource file
cat << 'EOF' > /tmp/confd-plugin-demo/conf.d/app.toml
[template]
src = "app.conf.tmpl"
dest = "/tmp/confd-plugin-demo/output/app.conf"
keys = [ "/app" ]
check_cmd = "grep -q 'Syntax:OK' {{.src}}"
reload_cmd = "echo '====> [PLUGIN RELOADED] Config updated via RPC! <===='"
EOF

# Create the template
cat << 'EOF' > /tmp/confd-plugin-demo/templates/app.conf.tmpl
# Generated by external confd plugin!
# Timestamp: {{datetime}}

{{if eq (getv "/app/feature_flags/maintenance") "true"}}
Syntax:INVALID (System is in maintenance)
{{else}}
Syntax:OK
{{end}}

[database]
endpoint = {{getv "/app/database/host"}}:{{getv "/app/database/port"}}
EOF
```

## 4. Test 1: One-Time Run via Plugin

Now, the moment of truth! We will launch `confd` using `--backend plugin` and provide it the path to our freshly compiled binary. 

*Note: Since the plugin is an external subprocess, it receives its configuration via environment variables.*

```bash
export CONFD_BACKEND_NODE="127.0.0.1:5432"
export CONFD_USERNAME="admin"
export CONFD_PASSWORD="secret"
export CONFD_DATABASE="confd"
export CONFD_TABLE="confd_config"

./bin/confd plugin \
  --plugin-path "./bin/confd-plugin-postgres" \
  --confdir /tmp/confd-plugin-demo \
  --onetime
```

If it works, `confd` will start the plugin subprocess, perform RPC calls to fetch the values, and generate the config file!

Verify the output:
```bash
cat /tmp/confd-plugin-demo/output/app.conf
```

## 5. Test 2: Daemon Mode & Real-time Polling

Let's run `confd` in the background, polling the database every 3 seconds via RPC calls to the plugin:

```bash
./bin/confd plugin \
  --plugin-path "./bin/confd-plugin-postgres" \
  --confdir /tmp/confd-plugin-demo \
  --log-level error \
  --interval 3 &

CONFD_PID=$!
```

> **Note:** We added `--log-level error` to keep your terminal perfectly clean. It will only shout if something breaks!

### 🎯 Trigger a Dynamic Update

In another terminal (or just copy-paste this), update the database to trigger an event:

```bash
docker compose -f test/docker-compose.yml exec -T postgres psql -U admin -d confd -c "
UPDATE confd_config SET value = '6432' WHERE key = '/app/database/port';
"
```

**👀 Expected Visual Output:**
Within 3 seconds, `confd` will silently query the plugin, see the new data, and execute the `reload_cmd`. You will see this pop up beautifully in your terminal:
```text
====> [PLUGIN RELOADED] Config updated via RPC! <====
```

## 6. Test 3: The "Bouncer" (Security & Validation)

Let's try to inject a completely invalid port number (`99999`) into our database. Normally, a dumb system would crash the app. But thanks to our PostgreSQL Trigger, the database acts as a bouncer!

```bash
docker compose -f test/docker-compose.yml exec -T postgres psql -U admin -d confd -c "
UPDATE confd_config SET value = '99999' WHERE key = '/app/database/port';
"
```

**👀 Expected Visual Output:**
The database will instantly violently reject the SQL command!
```text
ERROR:  Invalid port number: 99999
CONTEXT:  PL/pgSQL function validate_config() line 5 at RAISE
```
Because the DB rejected it, the plugin never sends the bad data to `confd`, and your system stays 100% safe!

## 7. Test 4: Graceful Syntax Rejection (Maintenance Mode)

Now, let's trigger the "Maintenance Mode". This time, the DB will accept the change, but our `confd` template will intentionally generate a bad syntax file (`Syntax:INVALID`). 
`confd`'s `check_cmd` will catch it!

```bash
docker compose -f test/docker-compose.yml exec -T postgres psql -U admin -d confd -c "
UPDATE confd_config SET value = 'true' WHERE key = '/app/feature_flags/maintenance';
"
```

**👀 Expected Visual Output:**
Because the syntax check fails, `confd` will refuse to apply the file and will throw an error to protect your production server:
```text
ERROR config check failed: exit status 1
```

To fix it and return to normal:
```bash
docker compose -f test/docker-compose.yml exec -T postgres psql -U admin -d confd -c "
UPDATE confd_config SET value = 'false' WHERE key = '/app/feature_flags/maintenance';
"
```
```text
====> [PLUGIN RELOADED] Config updated via RPC! <====
```

## 8. Test 5: Exploring the Audit Trail

Everything you just did via the plugin was permanently recorded by the `trigger_audit` inside the database. Let's look at the history!

```bash
docker compose -f test/docker-compose.yml exec -T postgres psql -U admin -d confd -c "
SELECT action, key, old_value, new_value, changed_at FROM config_audit ORDER BY changed_at DESC LIMIT 5;
"
```

**👀 Expected Visual Output:**
A beautiful table showing every state transition you performed during this demo!
```text
 action |              key               | old_value | new_value |         changed_at         
--------+--------------------------------+-----------+-----------+----------------------------
 UPDATE | /app/feature_flags/maintenance | true      | false     | 2026-04-30 14:00:15.123456
 UPDATE | /app/feature_flags/maintenance | false     | true      | 2026-04-30 14:00:10.654321
 UPDATE | /app/database/port             | 5432      | 6432      | 2026-04-30 13:59:45.987654

```

## 9. Stop Everything (Cleanup)

When you are done marveling at your new plugin architecture, kill the background process and clean the environment:

```bash
# Kill the confd daemon
pkill confd

# Stop and remove the Docker container
docker compose -f test/docker-compose.yml down -v

# Remove the demo directory
rm -rf /tmp/confd-plugin-demo
```
